# 关键词筛选与三个 AI 样例

运行 `python -m analysis` 仅更新全库关键词索引，不调用 API；
`python -m analysis --sample` 只处理 config/analysis.json 指定的三份政策；`python -m analysis --all` 处理全部关键词命中政策。
安装环境：`python -m pip install -r requirements-collector.txt`。
验证：`python -m unittest discover -s tests -p test_analysis.py -v`。

## 密钥与 Actions

1. 在 https://platform.deepseek.com/api_keys 登录、创建 API key，并确认账户有可用余额。
2. 仓库 Settings → Secrets and variables → Actions → New repository secret，名称 DEEPSEEK_API_KEY。
3. Actions → Analyze policies → Run workflow → scope 选择 all（全量）或 sample（三份样例）。无需将密钥写入代码或聊天。
4. 结果自动保存并提交 data/analysis/<政策ID>.json；无关文件保留政策原始记录。
   本地运行需事先通过安全方式设置 DEEPSEEK_API_KEY 环境变量。

## 数据与限制

- data/analysis-index.json：关键词、相关性、状态、visible；无关记录不展示；已判断相关但解读未完成的政策，前端保留原文与待核查提示，不展示未校验的模型内容。
- data/analysis/<ID>.json：原文链接、输入哈希、相关性及理由、summary/key_points/topics/targets/impact，
  impact 含 direction/reason；evidence 为对应三条要点的原文引句。统一标注“AI 生成，以原文为准”。
- v3 相关性与标签独立于摘要处理：原文不超过 3600 字时发送全文，否则保留前 1200 字及储能、电价、市场等实际条款附近的连续原文节选，截取时明确标待核查。要求逐项提供可核对的原文引句。解读发送正文与已解析附件，最多 12000 字；
  超限截取、正文不全或附件不完整均标“待核查”。这会漏掉仅附件里出现关键词的政策，遵循本版标题/正文规则。
- 要点优先具体规定与要求，不写背景形势；对象只含明确适用范围，不含参照执行；主题最多三项，按相关程度排序。
- 成功相关性判断立即缓存，成功解读不重复请求；内容、附件或规则版本改变会使结果失效（本次为 2026-09-29-v2）。
  解读字段/引用校验失败最多纠正一次；普通分析 API 失败不自动重试，保留错误供人工查看；本次重判任务只重试尚未通过校验的记录，每次尝试仍计入调用数和预算。
- 分析模块默认每次最多 300 次调用；自动发布使用 `--max-calls 50` 将相关性、解读与纠正请求合计限制为 50 次；每次请求前在 data/state/ai-budget.json 预占 0.2 元，每月最多预占 50 元。
  这是保守限额，不是实际账单；失败和中断也计入，实际 token usage 单独保存。
  按 2026-09-29 官方 Flash 峰时价（输入 $0.3/百万 token，输出 $1.2/百万 token），输入不超过 50000 UTF-8 字节、普通解读输出不超过1600 token；本次每批最多3份的重新分类输出上限2400 token，以保守换算10元/美元计算，重新分类单次上界约0.18元，预占0.2元；历史样例的每次1元预占不下调。不管理其他应用共用密钥的支出。
  改模型或价格变化后需复核预占额。官方定价：https://api-docs.deepseek.com/quick_start/pricing/。
- 结构、标签、数字存在性和引句校验不能证明语义完全准确；样例已获用户验收，本版按新规则重新生成样例并开放批量处理。
- 采集、分析、自动发布工作流共享 concurrency 组，避免同时写仓库。Astro 前端与北京时间每天 08:00 自动更新已接入，见 frontend.md。

样例分别为国家能源局《新型储能电站建设工程质量监督大纲》政策解读、
南方区域“两个细则”部分条款修订征求意见、广东省新型储能电站建设运行管理办法。
南方样例的正文主要为附件链接，解读会纳入两份已经解析的 PDF。

## 统计口径

`data/analysis-summary.json` 保存相关性数量、待核查数量和各主题数量；待核查可与三种相关性重叠，主题也可多选。`data/analysis-last-run.json` 记录当次实际请求次数（含失败/格式纠正，不含缓存跳过），月度历史详见预算账本。

## v3 相关性修订与跨网址去重

本次 scope 固定在 `data/reclassification-scope.json` 的 75 条原相关记录。标题 NFKC 规范化、统一引号并去空白，且明确发布日期相同的记录合并；选择已有解读的版本，保留所有原 URL、来源栏目和原始文件。75 条对应 73 份待重判政策；全库另有 2 组无关重复，共合并 4 组。

重新分类入口：Actions → Analyze policies → scope=reclassify（可断点续跑，不重复请求已完成组）；`python -m analysis.reclassify --max-calls 29`。每批最多3份，共同生成相关性、主题和影响对象及每项引句，只替换分类字段；摘要、核心要点、影响方向及其理由保持不变。`data/reclassification-v3.json` 保存原记录快照、结果、实际调用次数和是否全部完成。

- 直接相关：实际规定储能的规划、价格、补偿、考核、准入、安全标准，或电价/市场规则直接影响储能收益。
- 间接相关：没有直接规定储能，但电力市场、电价、新能源并网政策明确影响储能收益或发展空间。
- 无关：通用能源管理、国际合作、一般安全生产、节能审查等，仅出现储能字样不足以收录。
- 主题和对象逐项提供原文引句；无关文件清空分类标签，不删除既有摘要。结构与引句检查仍不能完全保证语义准确，保留待核查说明。

解释内容继续使用 v2 的内容指纹，分类版本独立记录为 `classification_version=2026-09-29-v3`，避免仅因分类规则变更而重付费生成摘要。日常增量自动使用 v3 分类；未完成解读只在政策库出现，首页动态仅显示 `status=complete`。

本轮实际发起 29 次请求，其中 65 份政策通过引句校验，剩余 8 份在预算保护触发后由助手阅读原文补齐；所有 73 份再作语义复核，纠正引句存在但不足以支持标签的情况。结果为直接相关 22 份、间接相关 12 份，其余 39 份不再计为相关。全库另有 15 份原已判无关，合计 54 份。`data/classification-review-v3.json` 明确记录复核方式不是人工验收、没有额外 API 调用；原模型输出留在审计文件。原摘要、要点、影响判断和引句均保留。
